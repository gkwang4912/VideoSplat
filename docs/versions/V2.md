# VideoSplat V2.0.0

**Status:** Release Candidate / Unreleased  
**Planned tag:** `v2.0.0`  
**Release date:** Unreleased

## V2 Overview

V2 replaces the V1 generated-video-first reconstruction flow with a known-camera-first workflow. It creates a 175-frame skeleton orbit and matching COLMAP poses before ComfyUI generation, then reuses those poses unchanged while building the Brush training dataset.

The authoritative technical analysis is [V2_ARCHITECTURE.md](./V2_ARCHITECTURE.md). The current bilingual usage documentation is [README.md](../../README.md) and [README_EN.md](../../README_EN.md).

## Core Features

- DWPose-guided skeleton extraction with silhouette fallback for missing detections.
- Deterministic 360-degree skeleton-control rendering and known COLMAP camera export.
- ComfyUI reference-to-video generation controlled by the skeleton orbit.
- BiRefNet/SAM3-based mask generation inside the checked-in workflow.
- Strict 175-frame RGBA, mask, and pose correspondence checks.
- Stage 3 binary-mask-to-alpha composition with exact alpha/mask validation.
- Brush dataset and ZIP export followed by batch 3D Gaussian Splatting training.

## Architecture

V2 consists of four stages under `src/`: `src/1_360_skeleton`, `src/2_suround_video`, `src/3_virtual_camera`, and `src/4_360brush`. The first two handoffs are manual; Stage 4 reads the Stage 3 output directly. There is no V2 Viewer or shared service.

## Pipeline

1. Generate an aligned character image, skeleton-control video, and known COLMAP poses.
2. Submit the aligned image and skeleton video to the ComfyUI workflow.
3. Combine the generated color/mask videos with the original camera model, write the binary mask into each RGB alpha channel, and validate the RGBA Brush dataset.
4. Run Brush directly against the Stage 3 output and export a Gaussian PLY.

## Dependencies

- Python 3.10+
- FFmpeg
- Packages in the root `requirements.txt`
- Two local DWPose ONNX models
- A compatible ComfyUI installation, custom nodes, and workflow model files
- A compatible Brush CLI selected through `VIDEOSPLAT_BRUSH_EXE` or PATH

## Installation

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

Install FFmpeg separately. Place the two DWPose model files described in `src/1_360_skeleton/models/README.md`. Configure ComfyUI from the node and model names in `src/2_suround_video/workflows/VideoSplat_2.json`. Set `VIDEOSPLAT_BRUSH_EXE` if Brush is not on PATH.

## Usage

Run the stages from the repository root after preparing each stage's `input/` and configuration:

```powershell
python -B src/1_360_skeleton/main.py
python src/2_suround_video/main.py --check
python src/2_suround_video/main.py
python src/3_virtual_camera/main.py
python src/4_360brush/main.py
```

The exact handoff layout is documented in the current README.

## Known Limitations

- V2 has no automated transfer for Stage 1 → 2 or Stage 2 → 3.
- DWPose and ComfyUI model weights are not distributed in Git.
- ComfyUI/custom-node/model versions are not pinned as one reproducible lockfile.
- The Stage 3 builder requires exactly 175 frames and preserves known poses; it does not estimate cameras.
- `points3D.txt` may be empty, so Brush can start from random initialization.
- V2 has no Viewer and only one focused RGBA handoff regression test, not a complete automated suite.
- Stage 3 produces RGBA plus separate masks and Stage 4 reads that output directly; the full path still requires validation in the target ComfyUI/Brush environment.
- The repository has no project-level LICENSE.
